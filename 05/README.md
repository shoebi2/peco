# 知覚・認知心理学 第5回「聴覚」（2026-10-23）演習ページ

GitHub Pages（`shoebi2/peco` の `05/`）で公開する、ブラウザだけで動く 2 つの聴覚実験と、その集計スクリプト。

| ファイル | 内容 |
|---|---|
| `index.html` | **課題B「音の高さの聞き分け」**（1000 Hz の周波数弁別、2 区間 2 肢強制選択、恒常法、72 試行、約 3 分）。全員が行い、結果コードを Google Form に貼る |
| `itd.html` | **体験A「左右のずれを聞く」**（両耳間時間差 ITD の側方化）。左右チェック → ITD を選んで聞き比べる体験 → 任意の測定（66 試行、約 2.5 分）→ 結果コード |
| `validate_itd.js` | `itd.html` の ITD 合成コードをオフラインで検証する Node スクリプト（相互相関で実際の ITD を測る） |
| `analysis_pitch.py` | Google Form の回答から結果コードを読み、全員を再推定し、図と要約表を書き出す Python スクリプト |

どちらのページも単一の HTML ファイルで、外部ライブラリやネットワークを使わない。音は Web Audio API で合成する。

## URL

- 課題B: `https://shoebi2.github.io/peco/05/`（`index.html`）
- 体験A: `https://shoebi2.github.io/peco/05/itd.html`

### URL パラメータ（動作確認用）

| パラメータ | 効果 |
|---|---|
| `?reps=1` | 各水準の反復回数を 1 にする（課題B: 12 試行、体験A: 11 試行）。既定は 6 |
| `?auto=1` | 模擬観察者が自動で回答し、結果画面まで進む（課題B: σ = 8 Hz、体験A: σ = 40 µs、λ = 0.02）。音は鳴らさない |

例: `index.html?auto=1&reps=1`

## 課題B（index.html）の流れと刺激

1. 教示（iPhone 向けの注意、テスト音ボタン）
2. 設定：参照音で音量合わせ、機材の自己申告（有線 / Bluetooth Apple / Bluetooth その他 / ヘッドホン / スピーカー）、音楽経験（0 年 / 1〜3 年 / 4 年以上）
3. 練習 4 試行（Δf = ±100 Hz、正誤フィードバックあり。3 問以上正解で合格。不合格でもやり直しか続行を選べる）
4. 本番 72 試行：Δf = ±1.5, ±3, ±6, ±12, ±24, ±48 Hz × 6、完全ランダム。フィードバックなし
5. 結果：心理測定関数、PSE、JND（Hz / % / セント）、結果コード、CSV 保存

刺激：標準音 1000 Hz 250 ms（10 ms cos² ランプ）→ 無音 500 ms → 比較音 1000 + Δf Hz 250 ms。各音の音量は ±3 dB（一様）でランダムに揺らす。左右同一（diotic）。1 試行を 1 つのステレオ AudioBuffer にして再生する。回答は 2 つ目の音が終わって 250 ms 後から受け付ける（↑ / ↓ キー、またはボタン）。

## 体験A（itd.html）の流れと刺激

1. 教示（両耳イヤホン必須、R を右耳、空間オーディオ／モノラルをオフ、音量合わせ、機材の自己申告）
2. 左右チェック 4 試行（左だけ／右だけの雑音、「どちらの耳？」）。間違いがあれば「左右を入れ替える」（ソフトで L/R を反転、`sw=1`）で再チェックできる
3. 体験パート：ITD = 0, ±15, ±30, ±60, ±120, ±240, ±600 µs のボタン。押すと雑音が鳴り、頭の図に位置を示す
4. 測定（任意）：単一刺激「左？ 右？」、ITD = 0, ±15, ±30, ±60, ±120, ±240 µs × 6 = 66 試行、完全ランダム
5. 結果：心理測定関数、PSE（µs）、JND（µs）、フラグ、結果コード、CSV 保存

刺激：300〜1200 Hz の帯域ガウス雑音 300 ms（20 ms cos² ランプ）。ITD は FFT の位相シフトで全波形（立ち上がりと持続部の両方）に与える（サンプル以下の遅延）。毎試行新しい雑音。左右は同じ係数で正規化（ピーク 0.3）。ITD > 0 = 右耳先行。StereoPannerNode・DelayNode は使わない。マイク（getUserMedia）は使わない。Huggins ピッチのヘッドホン検査は入れていない（ページを短く保つため）。

### 合成コードの検証

```
cd 05
node validate_itd.js
```

`itd.html` の `// === ITD-SYNTH BEGIN ===` 〜 `END` と `validate_itd.js` の同じ部分は同一のコードでなければならない（スクリプトが照合する）。相互相関＋放物線補間で推定した ITD は、44.1 kHz / 48 kHz とも全水準で要求値 ± 0.01 µs（2026-10-15 時点）。合成コードを変更したら両方を同じにして再実行する。

## 結果コードの書式

`|` 区切りの `key=value`。学生は「結果コードをコピー」ボタンで Google Form に貼る。末尾の `ck` は貼り付けミス検出用のチェックサム（`|ck=` より前の文字コードの合計を 36 で割った余りを base36 1 文字で）。

### PIT1（課題B）

```
PIT1|pse=-0.5|jnd=3.1|lam=0|n=72|hi=0.0.0.0.3.3.4.3.6.6.6.6|dev=W|mus=0|sr=44.1|ua=Oth.Chr|flag=-|id=j1k8|ck=9
```

| フィールド | 意味 |
|---|---|
| `pse` | PSE = μ（Hz、小数 1 桁） |
| `jnd` | JND = 0.674σ（Hz、小数 1 桁） |
| `lam` | 推定ラプス率 λ（0, 0.02, 0.04, 0.06, 0.08） |
| `n` | 本番の試行数 |
| `hi` | 各水準で「高い」と答えた回数。順序は固定で −48, −24, −12, −6, −3, −1.5, +1.5, +3, +6, +12, +24, +48 Hz |
| `dev` | 機材：W 有線 / BA Bluetooth（Apple）/ BO Bluetooth（その他）/ HP ヘッドホン / SP スピーカー |
| `mus` | 音楽経験：0（0 年）/ 1（1〜3 年）/ 4（4 年以上） |
| `sr` | AudioContext のサンプルレート ÷ 1000（44.1 / 48 など） |
| `ua` | OS.ブラウザ（iOS / And / Mac / Win / Oth . Saf / Chr / Fx / Oth） |
| `flag` | `F` 平坦（±48 Hz の正答率 < 75%）、`P` 練習不合格（最後の練習で 3/4 未満）。複数なら連結（`FP`）、なしは `-` |
| `id` | ランダム 4 文字（重複検出用。個人情報なし） |
| `ck` | チェックサム |

### ITD1（体験A）

```
ITD1|pse=7|jnd=22|lam=0.08|n=66|rc=0.2.0.0.2.4.3.5.4.5.6|lr=4/4|sw=0|dev=W|sr=44.1|ua=Oth.Chr|flag=-|id=cmqc|ck=s
```

| フィールド | 意味 |
|---|---|
| `pse`, `jnd` | µs（整数） |
| `rc` | 各水準で「右」と答えた回数。順序は −240, −120, −60, −30, −15, 0, +15, +30, +60, +120, +240 µs |
| `lr` | 最後の左右チェックの正答数 / 4 |
| `sw` | ソフトで左右を入れ替えたか（0 / 1） |
| `flag` | `F` 平坦（±240 µs の正答率 < 75%）、`O` 中心のずれ（\|PSE\| > 60 µs） |
| その他 | PIT1 と同じ（`mus` はない） |

## 集計（analysis_pitch.py）

```
pip install numpy pandas matplotlib scipy openpyxl   # scipy は任意、openpyxl は xlsx を読むとき
python analysis_pitch.py responses.csv                        # 結果コードの列は自動検出（全列を走査）
python analysis_pitch.py responses.xlsx --code-col 結果コード --out result_05
python analysis_pitch.py responses.csv --no-exclude-flat      # F を除外しない
python analysis_pitch.py --demo --out demo                    # 合成データで動作確認
```

出力：`figure/pitch_hist.png`（log JND のヒストグラム、音楽経験別）、`figure/pitch_class_pf.png`（プールした心理測定関数と音楽経験別の曲線）、`pitch_summary.csv`（学生ごとの再推定値と除外判定）、`pitch_groups.csv`（音楽経験別・機材別の要約、除外あり／なし）。ITD1 コードがあれば `figure/itd_hist.png`（JND と PSE の分布、機材別）と `itd_summary.csv`。

スクリプトはページ側の推定値を信用せず、`hi=` / `rc=` の回数データから同じモデルで全員を再推定する。チェックサム不一致のコードは既定で除外して件数を報告する（`--keep-bad-ck` で含める）。

### 固定した解析方針

- モデル：P = λ + (1 − 2λ)·Φ((x − μ)/σ)。格子探索の最尤法。課題B は μ ∈ [−60, 60] Hz（0.5 刻み）、σ ∈ [0.3, 300] Hz（対数 160 点）、λ ∈ {0, 0.02, 0.04, 0.06, 0.08}（0〜8% で推定）。体験A は μ ∈ [−240, 240] µs（1 刻み）、σ ∈ [4, 1000] µs
- PSE = μ、JND = 0.674σ（75% 点と PSE の差）。課題B は Weber 比 JND/1000 とセント 1200·log2(1 + JND/1000) も出す
- **除外（課題B）**：±48 Hz の正答率 < 75%（flag F）、または練習（±100 Hz）不合格（flag P）。除外あり／なしの両方を報告する
- **除外（体験A）**：F のみ除外。O（中心のずれ）は除外せず、機材別に分布を示す
- 音楽経験の群分け：0 年 / 1〜3 年 / 4 年以上
- 個人の推定値（66〜72 試行）の誤差は ±40〜50% 程度。クラスのヒストグラムと群比較が目的で、個人の精密測定ではない

## 機材の落とし穴（講義前に案内すること）

- **iPhone：イヤホンはページを開く前に接続する。** AudioContext を作った後に Bluetooth に切り替わると、音が速く／遅く再生される（WebKit bug 258864）。1000 Hz が約 1088 Hz になるなど。ページは Start ボタンで AudioContext を作る。あとからつないだ人はページを開き直す
- **iPhone のサイレントスイッチ**：Web Audio は着信音チャンネルで鳴るので、サイレントだと無音。ページは `navigator.audioSession.type = 'playback'` を試みるが、対応していない版もあるのでスイッチを切ってもらう
- **アプリ内ブラウザ（LINE、X、Instagram）**：クリップボードや音声が制限されることがある。Safari / Chrome で開く
- **Bluetooth 完全ワイヤレス（AirPods など）**：左右のレンダリング同期の設計目標が数十 µs 程度（Bluetooth SIG / BlueKitchen）。体験A では PSE のずれ（O フラグ）や曲線の緩さとして現れる。課題B は両耳同一の音なので影響しない。遅延 100〜300 ms は反応時間を無意味にするので、RT は解釈しない
- **空間オーディオ／Spatialize Stereo／Dolby Atmos／Windows Sonic**：両耳間の手がかりを壊す。体験A の前にオフ。iPhone：コントロールセンターで音量を長押し → 空間オーディオ → オフ。Windows：サウンド設定 → 空間サウンド → オフ
- **モノラルオーディオ（アクセシビリティ）と左右バランス**：モノラルは ITD を消す。バランスは ILD を加えて PSE をずらす。オフと中央に
- **L/R の付け間違い、片耳だけ、ゆるい装着**：左右チェックで検出。「左右を入れ替える」でソフト反転できる（`sw=1`）
- **マイクを要求しない**：Bluetooth イヤホンが HFP（モノラル・低音質）に切り替わるため。ページは getUserMedia を使わない
- **サンプルレートは指定しない**：ブラウザ既定のまま（`sr` に記録）。44.1 / 48 kHz の違いは ITD に影響しない（左右が同じ経路を通るため）
- **スピーカー**：課題B はできる（音量は控えめに）。体験A はできない（`dev=SP` は F になるはず）
- **教室の騒音と隣席からの音漏れ**：実施中は静かにし、開始をずらす。聴覚に不安のある学生や機材のない学生には不利益のない代替（見学・後日）を用意する
